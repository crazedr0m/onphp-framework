# Техническое задание: Этап 5 — Внедрение DI-контейнера

## Общая информация
- **Номер этапа:** 5
- **Название:** Внедрение DI-контейнера
- **Сроки:** 2 недели
- **Трудозатраты:** 2 человеко-недели
- **Приоритет:** Высокий

## Цель этапа
Интегрировать выбранный DI-контейнер в проект onPHP, настроить автовайринг для основных сервисов и обеспечить централизованное управление зависимостями.

## Задачи

### 1. Интегрировать выбранный DI-контейнер в проект
- **Описание:** Установить и настроить DI-контейнер (Symfony DI или PHP-DI) как зависимость проекта.
- **Действия:**
  1. Добавить выбранный контейнер в `composer.json` (например, `symfony/dependency-injection` и `symfony/config`).
  2. Создать базовую структуру конфигурации контейнера (например, файлы `services.yaml` или PHP-конфиги).
  3. Настроить автозагрузку сервисов через неймспейсы (если поддерживается).
  4. Обеспечить возможность кэширования конфигурации для production-среды.
- **Результат:** DI-контейнер установлен и готов к использованию.

### 2. Настроить автовайринг для основных сервисов
- **Описание:** Настроить контейнер для автоматического разрешения зависимостей основных сервисов (Configuration, CachePeer, ConnectionPool, DAO-воркеры и др.).
- **Действия:**
  1. Определить, какие сервисы будут управляться контейнером (список из предыдущих этапов).
  2. Для каждого сервиса создать конфигурацию (явную или через аннотации/атрибуты).
  3. Настроить автовайринг для интерфейсов и их реализаций.
  4. Регистрировать сервисы как shared (синглтоны) или как factory, в зависимости от их жизненного цикла.
- **Результат:** Контейнер может создавать все основные сервисы с автоматическим внедрением зависимостей.

### 3. Создать фабрику приложения (`Application`) для инициализации контейнера
- **Описание:** Разработать центральный класс `Application`, который инициализирует DI-контейнер и предоставляет доступ к сервисам.
- **Действия:**
  1. Создать класс `Onphp\Core\Application` с методами `getContainer()`, `getService($id)`.
  2. Реализовать построение контейнера на основе конфигурационных файлов.
  3. Обеспечить возможность переопределения конфигурации в проектах-потребителях.
  4. Добавить поддержку environment-specific конфигураций (dev, test, prod).
- **Результат:** Единая точка входа для получения сервисов.

### 4. Обновить точки входа (скрипты, веб-индекс) для использования контейнера
- **Описание:** Модифицировать основные скрипты инициализации onPHP (например, `global.inc.php.tpl`, веб-индекс) для создания и использования контейнера.
- **Действия:**
  1. В `global.inc.php.tpl` добавить создание экземпляра `Application` и регистрацию сервисов.
  2. Обновить примеры в `doc/examples/` для демонстрации работы с контейнером.
  3. Модифицировать тестовые bootstrap-файлы для использования контейнера в тестах.
  4. Обеспечить обратную совместимость: если контейнер не используется, фреймворк должен работать в legacy-режиме.
- **Результат:** Точки входа используют DI-контейнер для получения сервисов.

### 5. Написать документацию по конфигурации контейнера
- **Описание:** Создать руководство для разработчиков по настройке и использованию DI-контейнера в onPHP.
- **Действия:**
  1. Описать базовую конфигурацию сервисов.
  2. Привести примеры внедрения зависимостей в пользовательские классы.
  3. Объяснить, как переопределять сервисы в проектах.
  4. Добавить раздел по миграции с Singleton на DI.
- **Результат:** Документация доступна в `doc/` и онлайн.

## Критерии успеха
- [ ] DI-контейнер интегрирован и работает (проходит smoke-тест).
- [ ] Автовайринг настроен для основных сервисов (Configuration, CachePeer, ConnectionPool).
- [ ] Класс `Application` реализован и покрыт тестами.
- [ ] Точки входа обновлены и используют контейнер.
- [ ] Документация написана и доступна.
- [ ] Все существующие тесты проходят с использованием контейнера.

## Риски и митигация
- **Риск:** Конфликт версий зависимостей с существующим проектом.
  - **Митигация:** Тщательно подобрать версии, совместимые с PHP 7.4+, проверить в изолированной среде.
- **Риск:** Падение производительности из-за использования reflection в автовайринге.
  - **Митигация:** Включить кэширование конфигурации контейнера, использовать компиляцию в production.
- **Риск:** Усложнение процесса разработки для новичков.
  - **Митигация:** Предоставить шаблоны конфигурации, упрощённые примеры.
