# Техническое задание: Этап 1 — Инкапсуляция глобальных констант

## Общая информация
- **Номер этапа:** 1
- **Название:** Инкапсуляция глобальных констант
- **Сроки:** 2–3 недели
- **Трудозатраты:** 3 человеко-недели
- **Приоритет:** Высокий

## Цель этапа
Устранить использование глобальных констант для конфигурации путём инкапсуляции их в объект `Configuration` и внедрения зависимостей.

## Задачи

### 1. Создать класс `Onphp\Core\Configuration`
- **Описание:** Разработать класс, предоставляющий методы для получения значений, ранее хранившихся в глобальных константах.
- **Действия:**
  1. Определить интерфейс `ConfigurationInterface` с методами:
     - `getTempPath(): string`
     - `getIpcPerms(): int`
     - `getRootPath(): string`
     - `getCorePath(): string`
     - `getMainPath(): string`
     - `getMetaPath(): string`
     - `getVersion(): string`
     - `getClassCachePath(): string`
     - `getClassCacheType(): string`
     - и другие, соответствующие константам из `global.inc.php.tpl`.
  2. Реализовать класс `Configuration`, имплементирующий интерфейс.
  3. Реализовать возможность загрузки значений из массива (например, из конфигурационного файла).
  4. Добавить поддержку fallback к глобальным константам (для обратной совместимости).
- **Результат:** Класс `Configuration` с тестами.

### 2. Заменить прямые обращения к константам на инъекцию объекта `Configuration`
- **Описание:** Найти все использования глобальных констант в коде и заменить их на вызовы методов `Configuration`.
- **Действия:**
  1. Используя поиск, составить список файлов, где используются константы (например, `ONPHP_TEMP_PATH`, `ONPHP_IPC_PERMS` и т.д.).
  2. Для каждого файла:
     - Добавить зависимость на `ConfigurationInterface` в конструктор класса или метод.
     - Заменить `ONPHP_TEMP_PATH` на `$this->configuration->getTempPath()`.
     - Убедиться, что изменения не ломают логику.
  3. Основные файлы для изменения:
     - `core/Cache/FileLocker.class.php`
     - `core/Cache/DirectoryLocker.class.php`
     - `core/Cache/RubberFileSystem.class.php`
     - `main/Utils/FileUtils.class.php`
     - `main/DAOs/Handlers/FileSystemSegmentHandler.class.php`
     - и другие (всего около 100 мест).
- **Результат:** Код больше не содержит прямых обращений к глобальным константам (кроме fallback в `Configuration`).

### 3. Обновить `global.inc.php.tpl` для генерации экземпляра `Configuration`
- **Описание:** Модифицировать шаблон конфигурации, чтобы он создавал и настраивал объект `Configuration`.
- **Действия:**
  1. Добавить в `global.inc.php.tpl` создание экземпляра `Configuration` с передачей значений из констант (или напрямую из переменных).
  2. Зарегистрировать этот экземпляр в DI-контейнере (если контейнер уже интегрирован).
  3. Обеспечить, чтобы старый код, который всё ещё использует константы, продолжал работать (через fallback).
  4. Добавить deprecation warning при использовании констант (например, `trigger_error('Constant ONPHP_TEMP_PATH is deprecated', E_USER_DEPRECATED)`).
- **Результат:** Обновлённый `global.inc.php.tpl`, который создаёт `Configuration`.

### 4. Обеспечить обратную совместимость через fallback к константам
- **Описание:** Гарантировать, что существующие проекты, которые полагаются на глобальные константы, не сломаются.
- **Действия:**
  1. В классе `Configuration` реализовать логику: если константа определена, использовать её значение; иначе использовать значение по умолчанию.
  2. В местах, где константы используются напрямую, оставить fallback на случай, если `Configuration` не внедрён (например, в утилитных функциях).
  3. Написать интеграционные тесты, проверяющие, что старый и новый код работают идентично.
- **Результат:** Обратная совместимость сохранена, deprecation warnings выводятся в dev-среде.

### 5. Обновить документацию
- **Описание:** Отразить изменения в документации проекта.
- **Действия:**
  1. Обновить `doc/` файлы, описывающие конфигурацию.
  2. Добавить пример использования `Configuration` в `doc/examples/`.
  3. Обновить комментарии в коде (PHPDoc).
- **Результат:** Актуальная документация.

## Критерии успеха
- [ ] Класс `Configuration` реализован и покрыт unit-тестами.
- [ ] Все использования глобальных констант в ядре фреймворка заменены на инъекцию `Configuration`.
- [ ] `global.inc.php.tpl` обновлён и генерирует экземпляр `Configuration`.
- [ ] Обратная совместимость проверена: все существующие тесты проходят.
- [ ] Deprecation warnings добавлены для глобальных констант.
- [ ] Документация обновлена.

## Риски и митигация
- **Риск:** Большой объём изменений может привести к ошибкам в неочевидных местах.
  - **Митигация:** Проводить изменения постепенно, файл за файлом, с обязательным запуском тестов после каждого изменения.
- **Риск:** Падение производительности из-за дополнительных вызовов методов.
  - **Митигация:** Замерить производительность до и после изменений; оптимизировать кэширование значений в `Configuration`.
- **Риск:** Сложность внедрения `Configuration` в классы, которые не имеют доступа к DI-контейнеру.
  - **Митигация:** Использовать паттерн «Ленивая загрузка» или статический фасад временно (с последующим удалением на этапе 5).
